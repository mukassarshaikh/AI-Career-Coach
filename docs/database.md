# Database Schema
## AI Career Coach Platform — Postgres (Neon) + pgvector

Read `architecture.md` and `backend_architecture.md` first. This is the authoritative schema reference — SQLAlchemy models in `/backend/app/models` must match this exactly. All migrations go through Alembic; never hand-edit the schema.

---

## 1. Extensions

```sql
CREATE EXTENSION IF NOT EXISTS vector;   -- pgvector, for skill_vectors and market_skill_reference embeddings
CREATE EXTENSION IF NOT EXISTS pgcrypto; -- for gen_random_uuid()
```

## 4. Migration Strategy

- Alembic manages all schema changes. Workflow: modify SQLAlchemy models → `alembic revision --autogenerate -m "description"` → review generated migration → `alembic upgrade head`.
- Use a **Neon dev branch** for local development so migrations can be tested/reverted without touching production data; merge to main branch only when confirmed.
- Never edit a migration file that has already been applied to production — create a new migration to correct it instead.

---

## 5. pgvector Notes

- Embedding dimension must match whatever model generates the vectors (set in `embedding_service.py`). Keep `skill_vectors.vector` and `market_skill_reference.vector` at the **same dimension** — similarity comparisons require matching dimensions.
- Create the `ivfflat` index only after the `market_skill_reference` table has meaningful seed data (pgvector's index quality depends on having representative data to build lists from); an empty/near-empty table can be queried with a sequential scan in the meantime without an index.
